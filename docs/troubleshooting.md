# Troubleshooting

Every entry below was reproduced on Ubuntu 26.04.1 with PostgreSQL 18.6.

| What you see | Cause | Fix |
| --- | --- | --- |
| `service postgresql status` shows `active (exited)` | Normal. `postgresql.service` is a wrapper that exits immediately. | Check `pg_lsclusters` for `online`, or `systemctl status postgresql@18-main --no-pager` for `active (running)`. See [Install and verify](01-install-and-verify.md). |
| Output stops with `(END)` and a column of `~` | The output opened in the `less` pager. | Press `q`. Add `--no-pager` to `systemctl`, or `-P pager=off` to `psql`. |
| `FATAL: role "<name>" does not exist` | No role matches your Linux username. | Create one as the superuser: `CREATE ROLE <name> WITH LOGIN;`. See [Roles and authentication](02-roles-and-authentication.md). |
| `FATAL: Peer authentication failed for user "<name>"` | You used `-U` with a name that is not your Linux username, over the socket. A role that does not exist gives the same message. | Use `sudo -u postgres psql`, or connect as your own role. See [Roles and authentication](02-roles-and-authentication.md). |
| `fe_sendauth: no password supplied` | You connected over TCP (`-h 127.0.0.1` or `-h localhost`), which requires a password. | Supply the password, or leave out `-h` to use the local socket. See [Config and access rules](04-config-and-access-rules.md). |
| The prompt changes to `postgres-#` or `->` and nothing runs | The statement has no `;` yet. | Type `;` to run it, or `\r` to clear the buffer. See [First SQL](03-first-sql.md). |
| `cannot insert a non-DEFAULT value into column "id"` | You supplied a value for a `GENERATED ALWAYS` identity column. | Omit the column, add `OVERRIDING SYSTEM VALUE`, or define it as `GENERATED BY DEFAULT`. See [First SQL](03-first-sql.md). |

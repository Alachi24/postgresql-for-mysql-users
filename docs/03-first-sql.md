# Run your first SQL

> **Your username.** Examples show the author's Linux username, `chisa`. Run `whoami` to see yours. Wherever you see `<your-username>`, type your own name. Wherever you see `chisa` in an output, you will see yours.

Connect as your own role:

```bash
psql -d practice
```

The prompt is `practice=>`. The `>` means you are a regular role. The `postgres=#` prompt ends in `#` because that role is a superuser.

## Create a table and add a row

```sql
CREATE TABLE notes (
  id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);
-- CREATE TABLE

INSERT INTO notes (title) VALUES ('first note');
-- INSERT 0 1

SELECT * FROM notes;
```

```text
 id |   title    |          created_at
----+------------+-------------------------------
  1 | first note | 2026-11-16 14:14:14.353322+01
```

You never supplied `id` or `created_at`. The identity column and the default filled them in.

## What differs from MySQL

**`INSERT 0 1`.** The `0` is a leftover from when PostgreSQL returned an object ID. The `1` is the number of rows inserted. MySQL prints `Query OK, 1 row affected`.

**Database, schema, table.** The table lives in the `public` schema inside the `practice` database. In MySQL, "schema" and "database" mean the same thing.

**`TIMESTAMPTZ`.** It stores an absolute moment in time and displays it in the session's time zone (`+01` above). It is the usual choice in PostgreSQL. MySQL's closest type, `TIMESTAMP`, covers only 1970 to 2038.

**`TEXT`.** It has no length limit you need to manage (the practical maximum is 1 GB per value) and performs the same as `VARCHAR`. In MySQL, an index on a `TEXT` column must specify a prefix length.

## Identity columns vs `AUTO_INCREMENT`

Try inserting your own `id`:

```sql
INSERT INTO notes (id, title) VALUES (99, 'manual id');
```

```text
ERROR:  cannot insert a non-DEFAULT value into column "id"
DETAIL:  Column "id" is an identity column defined as GENERATED ALWAYS.
HINT:  Use OVERRIDING SYSTEM VALUE to override.
```

MySQL's `AUTO_INCREMENT` accepts a manual id and moves the counter forward. `GENERATED ALWAYS` refuses one unless you add `OVERRIDING SYSTEM VALUE`. `GENERATED BY DEFAULT AS IDENTITY` behaves more like MySQL. The failed insert changes nothing, so the table still has one row.

## When a statement does not run: the continuation prompt

`psql` runs a statement only when it sees a semicolon. Without one it waits for more input and changes the last-but-one character of the prompt from `=` to `-`:

```text
postgres=> SELECT current_user
postgres-> ;
 current_user
--------------
 chisa
(1 row)
```

- Type `;` to run what is in the buffer.
- Type `\r` to discard it and start over.
- The last character of the prompt shows your privilege level: `#` for a superuser, `>` for a normal role. As the superuser you would see `postgres=#` change to `postgres-#`.

The `mysql` client behaves the same way, with `mysql>` changing to `->`. A mismatched quote shows `'>` or `">` in both clients.
